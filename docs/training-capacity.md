# 训练容量估算（显存 / 时间 / 规模规划）

> 数据来源：本机实测（Windows 12 核 + RX 580 8G + DirectML）与标准 ResNet 激活开销经验值。
> 适用对象：src/cli 的本地模型训练（ResNet18 + CBAM，224px，fp32）。

## 1. 显存怎么算

显存 ≈ **激活值** + **权重/梯度/优化器状态** + **后端运行时开销**

`text
激活值 ≈ batch × 每张图的激活开销(224px) ≈ batch × 40 MB
权重   ≈ 参数量 × 4 B          (ResNet18+CBAM ≈ 1100 万参数 → 44 MB)
梯度   ≈ 权重
Adam   ≈ 权重 × 2              (exp_avg + exp_avg_sq)
FC 头  ≈ 512 × 类别数 × 4 B    (1000 类 ≈ 2 MB，可忽略)
`

### 1.1 batch = 32 时的明细（224px，1000 类）

| 项目 | 显存 |
|------|------|
| 激活值（40 MB/张 × 32） | ~1.3 GB |
| 权重 | ~45 MB |
| 梯度 | ~45 MB |
| Adam 动量 ×2 | ~90 MB |
| 1000 类 FC 头 | ~2 MB |
| DML 运行时 / 工作区 / 碎片 | ~0.5–1 GB |
| **合计** | **≈ 2.0–2.8 GB** |

**8GB 卡**宽裕（可上 batch 64）；**4GB 卡**勉强够（余量小，换 backbone 或调大分辨率就 OOM）。

### 1.2 两个缩放关系（记住这两条就够用）

| 变量 | 影响 |
|------|------|
| **batch** | 线性：×2 batch → 激活值 ×2 |
| **IMAGE_SIZE** | **平方**：224 → 320 ≈ ×2.04；224 → 448 ≈ ×4；224 → 160 ≈ ×0.51 |
| **backbone** | ResNet18 → ResNet50 ≈ ×3–4；→ EfficientNet-B0 ≈ ×1 左右 |
| **类别数** | 几乎无影响（只影响 FC 头） |
| **数据集张数** | **完全无影响**（显存只由 batch × 分辨率 × 模型决定） |

> 常见误解：以为"10 万张图要更多显存"。不会 —— 显存与数据集规模无关，只跟"一次喂进去多少"有关。

### 1.3 参考组合

| 组合 | 估算显存 | 4GB 卡 | 8GB 卡 |
|------|----------|--------|--------|
| ResNet18 @224, batch 8 | ~0.8–1.1 GB | ✅ | ✅ |
| ResNet18 @224, batch 32 | ~2.0–2.8 GB | ⚠️ 勉强 | ✅ |
| ResNet18 @320, batch 32 | ~4.5–6 GB | ❌ | ✅ |
| ResNet50 @224, batch 32 | ~4–5 GB | ❌ | ✅ |
| ResNet18 @224, batch 64 | ~4–5 GB | ❌ | ✅ |

### 1.4 显存不够时的办法

- **梯度累积**（`BATCH_SIZE=16` + 累积 2 步 = 等效 batch 32，峰值减半）：
  注意它**不减少前向/反向次数**，因此对 DirectML 的"逐算子提交开销"没有帮助
  （那正是 CPU 占用的来源，需要"更少、更大的步"）。
- 降 `IMAGE_SIZE`（平方收益，但会掉点）。
- 换更小的 backbone（一般不愿意）。

## 2. 时间怎么算

`text
每 epoch 时间 = 训练集张数 ÷ 吞吐(张/秒)
吞吐(张/秒)  = it/s × batch
总时间       = 每 epoch 时间 × 轮数  (受 EARLY_STOP_PATIENCE 影响)
`

### 2.1 本机实测基线（RX 580 + DirectML）

| 指标 | 实测值 |
|------|--------|
| batch 8 训练吞吐 | 1.87 it/s ≈ **15 张/秒** |
| GPU compute 占用 | **87%**（已接近该卡上限） |
| GPU 3D 占用 | ~2%（与训练无关） |
| CPU 占用 | ~20%（12 核 ≈ 2.4 核） |
| CPU 用途 | DataLoader 解码 + **DML 逐算子提交**（∝ 步数） |

### 2.2 规模外推

| 场景 | 吞吐 | 每 epoch | 50 轮合计 |
|------|------|----------|-----------|
| 1.7 万张（当前） | 15 张/s | ~19 分钟 | ~16 小时 |
| 10 万张 @batch8 | 15 张/s | ~1.85 小时 | **~3.9 天** |
| 10 万张 @batch32（乐观 25 张/s） | 25 张/s | ~1.1 小时 | **~2.3 天** |
| 10 万张 + ResNet50 | ~8 张/s | ~3.5 小时 | **~7 天** |

结论：**到 10 万张 / 1000 类这个量级，瓶颈是时间而不是显存**。

## 3. 已做过的训练加速（及其边界）

| 优化 | 提交 | 效果 |
|------|------|------|
| torch/torchvision 惰性加载 | `be355ea` | 空闲节点 464MB → 21MB（与训练无关，推理侧） |
| DirectML 权重加载改 CPU | `204d2a6` | 修复 DML 下 torch.load 崩溃 |
| 无 lerp 的 Adam（`AdamNoLerp`） | `985f405` / `5bfe6e2` | 消除每步 CPU 回退；foreach 路径把优化器 dispatch 从 ~700 次/步降到 ~8 次 |
| 降低每步设备同步 | `82326f7` | 每轮同步 1745×2~3 → ~90 次 |
| 数据集转 JPEG | `8650acf` | PNG 解码（本数据集 PNG 仅占 17%） |

**边界**：前三项消除的是"固定浪费"，但在 DML 上被**前向/反向的逐算子提交开销**掩盖（ResNet18 一步约 300–500 次 op 提交，∝ 步数）。
所以真正能改变量级的只有：**更大的 batch**（步数减半/减到 1/4）、**CPU 训练对比**、或**换 CUDA 显卡**。

### 3.1 怎么自己验证

`powershell
# 1) 看 GPU 是否真的在干活（compute 引擎占比接近 100% 说明是算力瓶颈）
(Get-Counter '\GPU Engine(*)\Utilization Percentage').CounterSamples |
  Where-Object CookedValue -gt 0 | Sort-Object CookedValue -Descending |
  Select-Object -First 5 InstanceName, CookedValue

# 2) CPU/DML 对比：改 .env 的 USE_DIRECTML，各跑 300 步，比较 it/s
USE_DIRECTML=false
`

## 4. 面向 1000 类 / 10 万张的规划建议

1. **显存**：batch 32 在 8GB 卡上没问题；4GB 卡上 batch 16 或 `IMAGE_SIZE=160`。
2. **时间**：本地方案（DML）50 轮 ≈ 2–4 天，ResNet50 ≈ 一周以上 —— 建议
   **训练放 CUDA 云 GPU**，本地 RX 580 只做推理/验证。
3. **精度**：183 → 1000 类是数量级跨越，ResNet18 的表达力会成为瓶颈，
   更大 backbone（ResNet50 / ConvNeXt-T / EfficientNet）几乎不可避免，而它同时把显存与时间再抬 3–4 倍。
4. **数据**：1000 类 × 平均 100 张是"够跑但偏薄"的规模，建议
   - 保持每类 ≥ 100 张，长尾类别优先补数据；
   - 用 `MAX_IMAGES_PER_ROLE` 控制上限，避免头部类碾压；
   - 训练集尽量包含**带背景的真实图**（实测：裁剪图域内 95%、原图整图 79%、原图+裁剪 71.3%，
     差距主要来自域差异与检测质量，见 docs/usage.md §8 与 §6）。
5. **续训友好**：权重统一以 CPU 张量保存、`config.json` 与权重/类别哈希同步更新，
   换机器继续训练不需要任何转换。

## 5. 快速估算公式（贴给未来的自己）

`text
显存(GB) ≈ batch × (IMAGE_SIZE/224)^2 × 0.040 + 0.0002 × 类别数 + DML开销(0.5~1)
         ResNet18: 0.040 GB/张 @224     ResNet50: ×3~4

时间(小时) = (训练集张数 ÷ (it/s × batch)) × 轮数 ÷ 3600
         RX580+DML 实测 it/s ≈ 1.87 @batch8（更大 batch 时 it/s 会略降，总吞吐上升）
`
