# 37AC 项目结构总结文档

**项目名称**: 37AC（Anime Character recognition）  
**项目类型**: 基于深度学习的二次元角色识别系统  
**架构**: 分布式C/S架构（中心服务器 + 边缘推理节点）  
**技术栈**: Python 3.12 + PyTorch 2.13 + Flask 3.1 + PHP + TCP Socket + MySQL  
**Web界面**: Flask Web服务 + PHP MVC Web应用（双前端架构）

## 核心组件分析

### 1. CLI客户端（边缘节点）
**路径**: `src/cli/`
- **主要功能**: 模型训练、图片推理、节点服务
- **核心文件**:
  - `main.py` - 主程序入口，提供交互式菜单（init_logging 在 main() 内调用，避免 DataLoader 子进程重复初始化）
  - `node_service.py` - TCP客户端，连接中心服务器
  - `predictor.py` - 图片推理功能
  - `trainer.py` - 模型训练功能

### 2. Web服务端（中心服务器）
**路径**: `src/server/`
- **主要功能**: RESTful API、任务分发、节点管理、用户认证、SSE实时推送
- **核心文件**:
  - `runserver.py` - 启动脚本（Flask + TCP双服务）
  - `services/listen_service.py` - TCP服务器，管理节点连接
  - `services/node_manager.py` - 节点注册、心跳、负载均衡、能力感知调度
  - `services/task_dispatcher.py` - 分发任务到空闲节点
  - `services/sse_bus.py` - SSE事件总线，实时推送结果到前端
  - `services/message_handlers.py` - 消息处理（注册/心跳/结果+SSE推送）
  - `services/auth_service.py` - JWT认证、用户注册/登录/刷新
  - `routes/` - 7个Blueprint路由模块（auth、upload、dashboard、node等）
  - `middleware/auth_middleware.py` - JWT登录/管理员装饰器
  - `middleware/rate_limiter.py` - 滑动窗口限流（基于唯一识别码，1s>5次触发429）

### 3. PHP Web应用（原生 MVC）
**路径**: `src/www/`
- **主要功能**: 现代化的仪表盘界面，基于自研 AC 设计系统「樱花拿铁」的响应式设计
- **核心文件**:
  - `router.php` - PHP路由控制器
  - `controllers/api_controller.php` - API 代理（X-API-Key 服务端注入）
  - `DASHBOARD.md` - 仪表盘功能详细说明
  - `SECURITY.md` - 安全配置文档
  - `start-server.bat` - Windows启动脚本
- **架构特点**:
  - **MVC模式**: 清晰的控制器、视图分离（无 Model 层，数据直连 Flask API）
  - **自研设计系统**: 樱花粉单强调色，自托管 Nunito/JetBrains Mono 字体与 Phosphor 图标，全站零外部 CDN
  - **仪表盘功能**: SPA 单页结构、统计卡片、节点管理、API 密钥、分页历史、系统设置
  - **组件化**: AC 组件库（按钮/卡片/表格/模态/Toast/骨架屏）复用
- **状态**: 功能完整，2026-08 完成全站重构

## 🔄 系统工作流程

### 训练流程
1. 用户运行 `python main.py`
2. 选择训练选项，加载数据集
3. **ResNet18 + CBAM 注意力机制** 模型训练（每层后插入通道+空间注意力）
4. 保存模型和类别文件到 `saves/` 目录

### 推理流程（YOLO 快速定位 + ResNet+CBAM 精确分类）
1. 图片上传后，**YOLOv8** 快速检测画面中的人物/主体区域，生成边界框
2. 裁剪出最佳检测区域（置信度最高），送入 **ResNet18 + CBAM 注意力** 进行角色分类
3. 若 YOLO 未检测到目标或未启用，自动降级为全图分类
4. YOLO 为可选模块，未安装 ultralytics 时自动降级

### 推理流程（当前，含SSE实时推送）
1. 用户通过PHP前端上传图片（支持裁剪/快速去背景/AI去背景）
2. 前端发送 `POST /upload` 到 Flask 后端（`Auth.fetch` 自动携带JWT令牌）
3. Flask后端接收图片、生成task_id、通过TCP分发到空闲节点
4. 前端通过 `EventSource /tasks/<task_id>/stream` 订阅实时结果
5. 节点推理完成 → TCP回传结果 → `sse_bus.publish()` → 前端即时收到
6. **降级方案**：SSE连接失败时自动回退到 `GET /tasks/<task_id>` 轮询
7. 结果展示：角色名称、置信度、概率分布条形图、萌娘百科链接

### 节点管理流程
1. 边缘节点启动 `node_service.py`
2. 连接中心服务器并注册（携带 `capabilities` JSON 数组 + `llm_enabled`/`llm_timeout_sec`）
3. 服务端 `NodeManager.register_node()` 存储节点能力，同步写入数据库 `nodes.capabilities` 字段
4. 节点 Token 以 **SHA-256 哈希**形式存入数据库（创建时可自定义或自动生成，仅返回一次）
5. 节点发送心跳检测
6. 服务端接收推理任务 → `task_dispatcher.dispatch_task()` 调用 `allocate_node_for_task(recognition_type)` 按能力匹配节点
7. 匹配的空闲节点接收任务并进行推理
8. 返回推理结果

### 能力感知分发机制
- 节点注册时通过 `capabilities` 字段（JSON 数组字符串，如 `["local","llm"]`）声明支持的能力
- 任务下发携带 `recognition_type`（local / llm / auto），服务端据此筛选具备相应能力的空闲节点
- 无匹配节点时降级到任意空闲节点并记录警告日志

### 节点归属权限（2026-08）
- 节点创建时自动归属当前登录用户（`user_id`）
- **普通用户**：仅能查看/修改/删除自己名下的节点
- **管理员**：拥有全部节点的管理权限
- 数据库层面通过 `WHERE user_id = %s` 强制约束，防止越权

### 任务智能重试（2026-08）
- 无空闲节点时任务进入等待队列，`task_manager` 后台线程定期重试
- 重试间隔按识别方式动态决策：
  - `local` → 10s（本地推理快）
  - `llm` → 90s 或节点上报 LLM 超时 +15s（避免推理中重复分发）
  - `auto` → 无在线 LLM 节点时走 10s 快路径，否则 90s 保守
- 前端 SSE 实时推送排队状态与预计重试时间，等待超时按识别方式动态调整

## ⚡ 技术特征

### 模型架构
- **主干网络**: ResNet18 + CBAM 注意力机制
- **注意力模块**:
  - `ChannelAttention`: 平均/最大池化 → 共享 MLP → Sigmoid，学习通道重要性
  - `SpatialAttention`: 通道平均/最大池化 → 7×7 卷积 → Sigmoid，学习空间重要性
  - 嵌入位置: 每个残差阶段（layer1~layer4）之后
  - 输入通道: layer1(64) → layer2(128) → layer3(256) → layer4(512)
- **分类器**: 单层 `nn.Linear(512, num_classes)`
- **⚠️ 注意**: 新增 CBAM 后旧权重不兼容，需重新训练

### 通信协议
- **传输层**: TCP长连接
- **协议类型**: 
  - JSON协议（注册、心跳、结果回传）
  - 二进制协议（任务下发、图片传输）
- **消息边界**: 长度前缀模式

### 数据流处理
1. **文本数据** → UTF-8编码的JSON
2. **二进制数据** → 原始字节流（图片等）
3. **严格区分** 避免解码错误

### 分布式特性
- **中心服务器**: Flask Web服务 + TCP服务
- **边缘节点**: 多个推理节点并行处理
- **负载均衡**: 自动选择空闲节点
- **能力感知调度**: 根据节点声明的 capabilities 匹配任务识别类型（local/LLM）
- **容错机制**: 心跳检测 + 自动重连

## 📊 配置与依赖

### 主要配置项
- **模型路径**: `MODEL_DIR`, `MODEL_PATH`, `CLASSES_TXT_PATH`
- **训练配置**: `DATASET_DIR`, `NUM_EPOCHS`, `BATCH_SIZE`, `IMAGE_SIZE`, `LEARNING_RATE`, `MODEL_FILENAME`, `YOLO_ENABLED`, `YOLO_CONFIDENCE`
- **调试模式**: `TSAC_DEBUG`，开启后日志级别为 `DEBUG`（关闭为 `INFO`），日志记录真实级别而非硬编码
- **网络端口**: `TCP_HOST`, `TCP_PORT`, `LOCAL_PORT`
- **心跳配置**: `HEARTBEAT_INTERVAL_SEC`, `HEARTBEAT_MISS_LIMIT`
- **安全配置**: `TOKEN`, `NODE_ID`
- **节点能力**: 根据 `LLM_RECOGNITION_ENABLED` 自动推导 `CAPABILITIES`（JSON 数组：`["local"]` 或 `["local","llm"]`）
- **任务重试**: `TASK_RETRY_INTERVAL_LOCAL` (10s), `TASK_RETRY_INTERVAL_LLM` (90s), `TASK_MAX_RETRIES` (3)
- **限流配置**: `RATE_LIMIT_ENABLED` (True), `RATE_LIMIT_REQUESTS` (5次/窗口), `RATE_LIMIT_WINDOW_SEC` (1s)
- **LLM识别**: `LLM_RECOGNITION_ENABLED`, `LLM_API_KEY`, `LLM_API_URL`, `LLM_MODEL_NAME`, `LLM_TIMEOUT_SEC`

## 🔄 系统工作流程

### 推理流程（当前，含SSE实时推送 + 异步LLM + 流式上传）
1. 用户通过PHP前端上传图片（默认快速模式：`recognition_type=auto`；高级模式可自定义识别方式和去背景）
2. **流式上传**（首选）：前端携带 `X-Stream-Response: true` 发 POST `/upload`，服务端直接返回 SSE 流，包含 queued → completed 全流程事件
3. **传统方式**（降级）：前端收到 JSON `{task_id}` 后连接 `EventSource /tasks/<task_id>/stream` 订阅实时结果，SSE 失败则回退到轮询
4. Flask后端接收图片、生成task_id、根据节点能力 dispatch 到空闲节点
5. 无空闲节点时任务进入等待队列，`TaskManager` 按间隔自动重试（local 10s / LLM 90s），SSE 连接保持不中断，节点上线后自动分发
6. 节点收到任务 → LLM推理在**后台线程**运行 → 主循环继续收发消息 → `pending_llm_tasks` 轮询完成结果
   - `auto` 模式：节点根据 `LLM_RECOGNITION_ENABLED` 自动选择 local/LLM
   - 限流保护：同一用户 1s 内超过 5 次请求触发 429
7. 节点结果回传 → `sse_bus.publish()` → 前端即时收到
8. 结果展示：角色名称（含萌娘百科链接）、置信度、识别方式、概率分布条形图
9. 若结果中包含 `error` 字段，前端直接显示错误提示

## 💡 使用建议

### 开发环境配置
1. **Python环境**: 配置Python虚拟环境，安装完整依赖
2. **PHP环境**: 配置 PHP 8.x（含 php-cgi.exe），部署 Nginx + PHP-CGI（详见 `docs/部署指南.md`）
3. **数据库**: 安装MySQL数据库，创建相应表结构

### 部署顺序
1. **启动Flask服务端**: 运行 `python src/server/runserver.py`
2. **启动PHP Web应用**: 运行 `src/www/start-nginx.bat`（Nginx + PHP-CGI 进程池，推荐）
3. **启动边缘节点**: 运行 `python src/cli/main.py` 并选择节点服务（或 `--mode 4`）

### 网络配置
1. **TCP端口**: 确保TCP端口可访问，防火墙设置正确
2. **Web端口**: Flask默认端口13138，PHP应用默认端口8000
3. **跨域配置**: 如有需要，配置CORS允许跨域请求

### 数据准备
1. **训练数据**: 按照要求准备训练数据集，每个角色至少100张图片
2. **模型文件**: 确保模型文件路径配置正确
3. **数据库**: 创建必要的数据库表结构

### 访问方式
- **PHP仪表盘**: `http://localhost:8000/dashboard`
- **API接口**: Flask服务提供的RESTful API `http://localhost:13138`

**项目状态**: 功能完整，文档基本齐全，架构稳定，支持双前端架构
